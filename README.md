# ANIME DRAWER

Настольное приложение на Python/PySide6: импортирует изображение, строит план цветных штрихов и исполняет его обычным вводом Windows. Есть локальный тестовый холст, захват выбранной области персонажа и необязательный облачный Images API. CUDA и локальная нейросеть не нужны.

**Статус:** функциональная исходная версия, проверенная на Linux в локальном Qt-холсте. Win32-бэкенд реализован, но его выполнение на Windows, приём ввода Roblox и Windows EXE в этой среде не проверены. Это не заявление о готовности к использованию непосредственно в игре.

## Быстрый запуск на Windows

Нужны Windows 10/11 x64 и Python 3.11–3.13 x64 с Python Launcher или доступный в PATH. Скрипт сначала проверяет существующее окружение, затем ищет подходящую установленную версию. Зафиксированная версия PySide6 не поддерживает Python 3.14+. Распакуйте весь проект в обычную папку.

```bat
run.bat
```

Первый запуск создаст короткое окружение в `%LOCALAPPDATA%\AD\envs` и установит зависимости. Оно находится отдельно от проекта, чтобы длинные имена папок GitHub ZIP не мешали установке Qt при лимите Windows в 260 символов. Версия Python и зависимости определяют отдельную папку кэша; одинаковые копии проекта используют одно исправное окружение. Незавершённая установка повторяется при следующем запуске. При ошибке окно остаётся открытым, а подробности записываются в `logs\startup.log`. Путь выбранного Python сохраняется в `logs\python-path.txt`. Если Python не найден, выводится инструкция по установке. Или вручную:

```bat
py -3.11 -m venv .venv-win
.venv-win\Scripts\python.exe -m pip install -r requirements.txt
.venv-win\Scripts\python.exe main.py
```

Запуск с открытым тестовым холстом:

```bat
run.bat --test-canvas
```

Плавающую иконку можно перетаскивать; левый клик открывает панель, правый — прозрачность и выход. Закрытие панели оставляет иконку. Для выхода выберите «Выход» в меню иконки. Во время рисования панель, иконка и debug overlay скрываются, чтобы не перекрывать целевое окно.

## Первый рисунок на локальном холсте

1. Нажмите **TOOLS → LOCAL CANVAS**. Приложение создаст профиль известных кнопок цветов и размеров кисти. На Windows этот холст использует настоящий `SendInput`; на Linux — события мыши только внутри Qt-приложения. AI SETTINGS, CROP IMAGE, операции с кэшем и DEBUG OVERLAY также находятся в TOOLS.
2. Нажмите **TEST DRAW** и явно разрешите тестовую линию. Программа сравнит пиксели тестового участка и попросит визуально подтвердить цвет и толщину. Отрицательный результат не подтверждает профиль.
3. Очистите холст кнопкой **CLEAR**.
4. Нажмите **IMPORT IMAGE**, выберите PNG/JPEG/WEBP, например `assets/sample_character.png`. Также работают перетаскивание файла и Ctrl+V из буфера, когда фокус вне текстового поля.
5. Выберите качество, скорость и лимит. Для первого полного теста используйте **Unlimited**. Нажмите **PREVIEW**.
6. Сравните ORIGINAL, PROCESSED и DRAW PREVIEW. Последний показывает именно рассчитанные штрихи, а не исходник.
7. Нажмите **RUN**. После активации холста и задержки на перерисовку приложение само выбирает цвета, размеры и выполняет штрихи.

**F8** — пауза/продолжение. **F9** — аварийная остановка с отпусканием кнопки мыши. На Windows это глобальные зарегистрированные клавиши. Если их заняла другая программа, RUN блокируется. На Linux они действуют в окнах ANIME DRAWER, поскольку внешняя автоматизация там не поддерживается.

При паузе незавершённый штрих будет выполнен заново, а завершённые пропускаются. После STOP следующий RUN начинает новый рисунок: автоматического продолжения после закрытия программы или ошибки фокуса нет.

## Калибровка Roblox

Используйте оконный или безрамочный режим. Откройте постоянную палитру и инструменты, подготовьте **пустой белый холст**, выберите непрозрачность кисти **100%**. Roblox и ANIME DRAWER должны работать с одинаковыми правами Windows.

1. Нажмите **CALIBRATE**, выберите нужное окно. Программа скроет свои окна и получит снимок клиентской области через MSS.
2. Укажите два противоположных угла рисуемой области **внутри рамки**. Координаты хранятся относительно клиентской области окна, а не всего монитора.
3. При необходимости укажите кнопку инструмента кисти.
4. Нажимайте **+ Цвет палитры**, выбирайте центр постоянного цветового образца и подтверждайте RGB реально рисуемого цвета. Добавьте все используемые цвета. Планировщик будет выбирать только из этой палитры.
5. Через **+ Размер кисти** добавьте доступные кнопки размеров и реальные толщины следа в **физических пикселях**, а не просто число из подписи игрового ползунка. Полезный набор — тонкая, средняя и широкая кисть.
6. Если есть однотонный индикатор текущего цвета, отметьте его. Это позволяет проверять цвет после переключения; несовпадение останавливает исполнение.
7. Для Character выделите область только нужного персонажа. Ручная область обязательна: программа не угадывает, какой из соседних игроков ваш.
8. Сохраните профиль. Выполните **TEST DRAW**, проверьте результат и остальные выбранные образцы/размеры. Очистите холст перед полноценным RUN.

Профили сохраняются между запусками. Сдвиг окна **до** RUN допустим: координаты пересчитываются относительно нового положения. Во время рисования сдвиг, изменение размеров/DPI, потеря фокуса, закрытие окна или перекрытие точки другим окном останавливают ввод. При изменении разрешения, масштаба Windows или интерфейса повторите калибровку. Стабильные пиксели образцов палитры дополнительно проверяются на изменение расположения; это не универсальный детектор всех возможных изменений интерфейса.

**DEBUG OVERLAY** показывает границы и точки на 7 секунд. При RUN он скрывается. Работа overlay на смешанных DPI требует отдельной проверки на Windows; окончательный ориентир — TEST DRAW.

Если обычный Windows-ввод не принимается игрой, проверьте фокус, кисть, открытое состояние палитры и координаты. Программа не обходит игровые ограничения и не объявляет успешным тест без изменения изображения и визуального подтверждения.

### Палитра и инструменты

Эта версия использует **калиброванные постоянные цветовые образцы и кнопки размеров**. Она не предполагает наличие рабочей заливки. Области закрашиваются широкими параллельными штрихами, границы — упрощёнными полилиниями.

Автоматическое управление непроверенным цветовым кругом, HSV-слайдерами, текстовыми RGB-полями и непрозрачностью не включено. Если игра предлагает только такие элементы, для неё требуется отдельный адаптер и проверка реального интерфейса. Исходный запрос ссылался на скриншот, но сам скриншот не был предоставлен; геометрия игрового UI не выдумывалась.

## Режимы источника

**Image:** импорт и локальная обработка без API. CROP IMAGE обрезает по двум точкам. «Заполнить кадр обрезкой» масштабирует с обрезкой по центру; иначе изображение вписывается с белыми полями. GrabCut — необязательная эвристика удаления фона, она может ошибаться.

**Character:** после калибровки области нажмите CAPTURE. PREVIEW готовит захваченный фрагмент локально. GENERATE отправляет исходный захват и описание в AI для художественной интерпретации. Повторная генерация использует сохранённый захват, а не предыдущий результат AI.

**Text:** введите PROMPT и нажмите GENERATE. После генерации всегда показывается изображение; рисование требует отдельных PREVIEW и RUN.

Стиль Anime/Detailed Anime сам по себе **не превращает** импорт в нейросетевой аниме-рисунок. Для этого нужен генеративный API. Black & White/Manga, Sketch, Comic и Pixel Art используют локальные фильтры. Custom оставляет локальное изображение без дополнительного стилевого фильтра; произвольный AI-стиль задаётся в PROMPT.

## Подключение AI

Откройте **AI SETTINGS**:

- HTTPS base URL, например `https://api.openai.com/v1`;
- image model, по умолчанию `gpt-image-1`;
- API key, сохраняемый через `keyring` в системное хранилище Windows.

Альтернатива — переменная `ANIME_DRAWER_API_KEY`, которая имеет приоритет над keyring. Ключи не записываются в JSON, историю или исходники. Значение ключа в чате не требуется. Поддерживается Images API: JSON `/images/generations` для текста и multipart `/images/edits` с PNG для reference image. Совместимость конкретного стороннего провайдера зависит от его Images API.

Перед отправкой показывается адрес провайдера и подтверждение передачи описания/изображения. API может быть платным. Ответ принимается в `b64_json` либо по HTTPS URL; на запрос загрузки со стороннего хранилища заголовок API-авторизации не передаётся. TLS-проверка включена. STOP отбрасывает результат отменённой генерации; удалённый платный запрос может продолжиться. Сетевой таймаут ограничивает ожидание.

Живой API в ходе разработки не вызывался: проверены HTTP-контракт, multipart-передача reference, обработка ошибок и отсутствие утечки авторизации на запрос к хранилищу с помощью MockTransport.

## Качество и время

Планирование включает сегментацию по ограниченной палитре, выделение контуров, Ramer–Douglas–Peucker, широкие линии для площадей, мелкие контуры в конце и группировку по цвету/кисти. Заполнение не состоит из отдельных кликов по каждому пикселю.

Оценка учитывает длину пути, частоту событий, переключения инструментов и запас на накладные расходы. Safe/Normal/Fast задают задержки обычного ввода. Реальная скорость и принятие событий зависят от игры.

При превышении лимита алгоритм пробует снизить разрешение сегментации и количество цветов, сохраняя доступный тёмный контур и белый фон. Для калиброванной палитры используется подмножество реальных образцов, новые цвета/размеры не выдумываются. Сетка заполнения учитывает физическую ширину кисти, чтобы уменьшение детализации не создавало разреженные полосы. Если ни один вариант не укладывается, сохраняется исходное качество и RUN отказывается запускать рисунок с этим лимитом. Во время исполнения есть отдельная проверка крайнего времени; таймер раунда продолжает идти на паузе. Auto означает консервативный лимит 165 с, **OCR таймера не реализован**.

Приоритеты геометрические: цветовые области, затем контуры. Семантическое распознавание лица/глаз, нейросетевая оценка важности и обещание профессионального качества за 165 секунд не реализованы. В предпросмотре видно, какие детали сохраняются при доступных кистях и палитре.

## Сохранение

По умолчанию данные находятся в `%LOCALAPPDATA%\AnimeDrawer` на Windows или `~/.local/share/anime-drawer` на Linux. Для отдельного каталога задайте `ANIME_DRAWER_DATA_DIR`.

- `settings.json`: параметры обработки, положение/прозрачность иконки, адрес и модель AI;
- `profiles.json`: профили холста, области персонажа, палитры, кистей и проверок;
- `plans/`: автоматический кэш, учитывающий исходник и содержимое плана;
- `images/`, `history.json`: локальные изображения и история импорта/генерации/исполнения.

SAVE PLAN экспортирует JSON, LOAD PLAN позволяет повторить рисунок без обработки. RUN заново проверяет размер холста, цвета и кисти плана. История хранит последние 200 записей; архивы изображений и планов можно удалять вручную. PREVIEW в истории — расчётный результат; это не автоматически снятый скриншот завершённого рисунка Roblox. Ошибка чтения настроек не приводит к молчаливой перезаписи исходного файла.

## Тесты и проверка настоящего ввода

После успешного `run.bat` выполните в PowerShell в папке проекта:

```powershell
$python = (Get-Content -Raw -Encoding UTF8 .\logs\python-path.txt).Trim()
& $python -m pip install -r requirements-dev.txt
& $python -m pytest -q
```

Автотесты проверяют геометрию, отрицательные координаты мониторов, ограничения профиля, импорт, сегментацию и точность областей, RDP, бюджет, кэш и JSON, состояние мыши, паузу/повтор штриха, STOP, потерю фокуса, сдвиг окна, изменение DPI, перекрытие и проверку цвета. Два интеграционных теста проходят путь от планирования/интерфейса до фактических цветных пикселей **локального Qt-холста**.

На интерактивном Windows-компьютере отдельно выполните:

```powershell
$python = (Get-Content -Raw -Encoding UTF8 .\logs\python-path.txt).Trim()
& $python tools\native_smoke.py
```

Этот скрипт использует настоящий `SendInput`, рисует две линии только в собственном тестовом окне, проверяет их цвета и пишет `artifacts/native-smoke.json` и PNG. F9 прерывает исполнение. Он не запускается на Linux или в headless CI и пока здесь не был выполнен.

Для Linux/cloud:

```sh
bash tools/cloud_install.sh
QT_QPA_PLATFORM=offscreen .venv/bin/python -m pytest -q
```

При наличии обычного Linux-дисплея можно запустить `python main.py --test-canvas`, но внешний Win32-ввод недоступен. Offscreen-тесты не создают пользовательский веб-предпросмотр.

## Сборка EXE

Собирайте **на Windows**, не на Linux:

```bat
build.bat
```

Скрипт устанавливает зависимости, запускает тесты и вызывает PyInstaller. Результат: `dist\AnimeDrawer\AnimeDrawer.exe`. Передавайте **всю папку** `AnimeDrawer`, включая `_internal`; это onedir-сборка. Она не требует установленного Python на целевом ПК. Автоматическая сборка также описана в `.github/workflows/windows.yml`; workflow ещё не запускался из этой среды.

Готовый Windows EXE в Linux-среде не создан. Сборка и приёмочные проверки Windows остаются обязательными перед распространением. Исходный ZIP не является EXE.

## Архитектура

```text
main.py                      точка входа
app/models.py                координаты, калибровка, штрихи, тайминги, сериализация
app/imaging.py               импорт, подготовка, локальные фильтры
app/planner.py               сегментация, заполнения, контуры, план и предпросмотр
app/automation.py            исполнитель, пауза, STOP, контроль фокуса и геометрии
app/windows.py               DPI, окна, MSS, SendInput, глобальные горячие клавиши
app/ai.py                    интерфейс провайдера, Images API, keyring
app/storage.py               атомарное сохранение JSON, планы, изображения, история
app/ui/                      панель, иконка, калибровка, overlay, тестовый холст, потоки
tests/                       unit- и интеграционные тесты
tools/native_smoke.py         реальная проверка Win32 на интерактивном рабочем столе
build.bat / run.bat           сборка и запуск Windows
```

Обработка, AI и рисование выполняются в рабочих потоках. Прогресс обработки соответствует выполненным этапам; при ожидании AI используется неопределённый индикатор. Roblox-процессы не модифицируются, память игры не читается, код в игру не внедряется. Если обычный ввод не принимается, программа останавливается и сообщает об ограничении.
