# REDLAIN 3.0 — проверки, скорость и границы результата

Проверка 2026-10-23: Python 3.12, Linux, PySide6 6.8.3, Qt offscreen. Исходная версия: `ee7c55d1062efd412c3767b2eec2194e68c1e1db` (227 тестов). Финальная регрессия: **261 passed**, код завершения **0**; повторная полная проверка также завершилась без сбоя. В ходе разработки найден и исправлен сбой освобождения обёртки главного QThread: GuiBridge сравнивает идентификатор своего потока без создания временной Python-обёртки QThread.

## Что реально измерялось

`tools/benchmark_v2.py` воспроизвёл исходную версию: [baseline JSON](v3-baseline.json). `tools/benchmark_v3.py` исполнил пять вариантов на тех же PNG, палитре, кистях 3/9/18 px и физическом участке 128×128 встроенного Qt-холста: [полные результаты](v3-benchmark.json).

Это **фактически доставленные и нарисованные Qt-события**, включая выбор цвета/кисти, время ожиданий, отпускание мыши и длины движений. Это не умножение старой оценки на желаемый коэффициент. Для изоляции стоимости плана используется ускоренный локальный тестовый Timing `event=.0001, settle=.0001, pps=1e6, sample=40`. Он одинаков у сравниваемых движков и **не является пресетом для Roblox**. Протокол не измеряет задержки сервера, Win32 SendInput или ввод RGB в игровом UI.

| Пример | Vector 2.0: мазки / фактическое время | FAST | BALANCED | MASTERPIECE | FAST быстрее Vector |
| --- | --- | --- | --- | --- | --- |
| portrait | 132 / 7,487 с | 15 / 2,622 с | 31 / 4,231 с | 49 / 5,004 с | 2,86× |
| landscape | 141 / 8,505 с | 21 / 3,568 с | 35 / 4,326 с | 69 / 4,700 с | 2,38× |
| texture_text | 73 / 8,046 с | 20 / 2,977 с | 20 / 3,336 с | 20 / 4,116 с | 2,70× |

Legacy на этих же примерах: 80 / 7,016 с; 113 / 7,398 с; 55 / 6,896 с. Само исполнение FAST быстрее Legacy примерно 2,07–2,68×. Результат не подтверждает обещание 10–20×; такого утверждения в продукте нет.

Диагностика затрат на portrait: Vector → FAST сокращает перемещения мыши **2322 → 809**, нажатия **143 → 20**, запросы цвета **7 → 2**, запросы кисти **5 → 4**. Для landscape: нажатия **179 → 36**, запросы цвета **24 → 5**. Показатели `color_requests`/`brush_requests` считают реальные обращения к контроллерам; дополнительные `color_changes`/`brush_changes` на этом локальном backend равны нулю, поэтому они не выдаются за количество подтверждённых игровых переключений. У каждого результата доступны фактические wait_seconds, длины пути, planning_seconds и received_segments.

## Качество и компромиссы

Pixel agreement — доля пикселей с ошибкой RGB в пределах порога теста; это вспомогательная метрика, а не эстетическая оценка или гарантия качества лица. На маленьком участке с кистью минимум 3 px края сглаживаются Qt иначе, чем Pillow-preview.

| Пример | Vector: согласие пикселей | FAST | BALANCED | MASTERPIECE |
| --- | --- | --- | --- | --- |
| portrait | 95,1% | 95,1% | 95,4% | 95,4% |
| landscape | 94,8% | 92,3% | 93,5% | 93,5% |
| texture_text | 77,9% | 89,0% | 88,9% | 89,0% |

На landscape новый алгоритм теряет часть точности краёв относительно Vector. FAST намеренно удаляет больше деталей. MASTERPIECE не гарантирует превосходство по каждому пикселю или больше мазков на каждом простом рисунке: меняются допустимый шум, число цветов, точность кривых и коррекция покрытия. Число корректирующих траекторий ограничено (FAST 0, BALANCED 24, MASTERPIECE 256), чтобы не возвращаться к неограниченному рисованию точек. Реальная игра может рисовать кистью иной формы: нужна нативная проверка.

## Что ещё зависит от среды

- **Windows/Roblox:** SendInput, DPI, задержки игровых полей, серверные отключения, EXE и прохождение четырёх скоростей требуют выполнения [нативного сценария](WINDOWS_ROBLOX_TEST_RU.md). В Linux нет клиента Roblox. Windows CI/сборка описаны, но не выдаются за выполненные здесь.
- **Commons:** реальная попытка официального API в этой облачной сессии вернула ProxyError 403. Дополнительные домены commons.wikimedia.org/upload.wikimedia.org сохранены в черновике настройки среды; этот черновик ещё не применён. Ограничение не обходилось. Тесты транспорта проверяют код интеграции, а не доступность живого сервиса. В Windows нужен обычный доступ к этим двум доменам, ключ не нужен.
- **AI-генерация:** прежний внешний Images API требует ключ и адрес/модель в AI SETTINGS. Остальные функции работают без этого.
- **Сегментация:** локальные цветовые/геометрические эвристики, контраст, границы и опциональные детекторы OpenCV; нет обещания семантического распознавания любых аниме-глаз/рук/волос. Важные области можно указать вручную.
- **Холст:** сохраняется план приложения, а не сервер Roblox. При исчезновении рисунка продолжение с середины не восстановит фон. Несохранённый прогресс 2.0 не мигрирует из памяти закрытого процесса.
- **Прозрачность/точность:** наложение полупрозрачных мазков меняет цвет; для копии — 100%. Слишком мелкие детали/шрифт не воспроизводятся минимальной игровой кистью; смотрите DRAW PREVIEW и заметки о непрокрашиваемых пикселях.
- **AUTO EXTEND:** продолжение краёв, не генеративная дорисовка новых объектов. Произвольного AI-outpainting без API нет.

Без нативной проверки нельзя гарантировать отсутствие всех ошибок Roblox, универсальное художественное превосходство или фиксированное время для сложного исходника.
