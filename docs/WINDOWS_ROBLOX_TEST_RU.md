# Проверка REDLAIN 3.0 на Windows и в Roblox

Эта проверка требует живого клиента игры. В Linux/cloud нет Win32 SendInput, сервера Roblox и вашего сохранённого холста. Успешный локальный Qt-тест не заменяет эти шаги. Проверяйте на своей тестовой работе, которую можно очистить вручную.

## Подготовка

1. Windows 10/11 x64, Python 3.11–3.13 x64. Распаковать ZIP, запустить run.bat, проверить заголовок REDLAIN DRAW ENGINE 3.0.
2. Открыть игру с чистым белым холстом. Для готового профиля клиентская область — 1366×768, прежние точки/масштаб игры; иначе CALIBRATE. У программы и Roblox одинаковые права.
3. Убедиться, что F8/F9 зарегистрировались. Проверить остановку на локальном холсте до внешней автоматизации.
4. RGB-плейс: открыть/закрыть палитру цветным кругом, убедиться, что поля RGB и размера доступны для ввода. Старый плейс: бесплатный размер 1–256, непрозрачность 100% слева → 1% справа. Донатные вкладки/6–8 не использовать.

## Приём ввода и скорости

1. Normal, задержка 250 ms, непрозрачность 100%. CHECK BRUSH SIZE: реальные числа должны заменяться, не дописываться. В RGB-профиле проверить переходы 255 → 0 → 128 в каждом канале: старое число удаляется, новое вводится, Enter фиксирует.
2. TEST DRAW на чистом холсте: линии появляются только в ожидаемой зоне, нет хвоста от палитры к началу, верны чёрный/красный/зелёный и толщина. Отрицательный результат не подтверждать. Сохранить logs/test-draw.json и снимок.
3. Очистить вручную. SPEED CALIBRATION: разрешить четыре длинных штриха, не двигать мышь. Проверить отсутствие разрывов, углов и следов далеко от ожидаемой траектории. Сохранить logs/speed-calibration.json. Рекомендация должна опираться на прошедшие линии; пропущенные быстрые линии не должны подтверждать Sprint.
4. Очистить. Выбрать рекомендованную скорость; не отключать проверку цвета/кисти. При недостоверном чтении/пропуске — Safe/Normal и большая задержка, повторная калибровка.

## Одинаковый рисунок в трёх режимах

Для assets/v2-examples/portrait.png, landscape.png и texture_text.png выполнить отдельно FAST, BALANCED, MASTERPIECE с одним профилем, форматом, 100% масштабом, скоростью и непрозрачностью. После каждого запуска очищать холст вручную. Сохранять проект и фото результата.

Зафиксировать wall-clock, фактически принятые мазки, переключения цветов/кистей, реальные пропуски и качество границ. Сравнить с Vector 2.0 на **том же** изображении и профиле. Режимы могут дать одинаковый план на простом рисунке; на сложном FAST должен удалять больше деталей. Обязательное условие: снижение времени не достигается пропущенными линиями.

Проверить виртуальные этапы по Live Art Core и журналу плана. Большие области должны содержать длинные траектории/крупные кисти, а не тысячи одиночных точек. Число фаз с мазками зависит от содержания: в плоском логотипе может не быть отдельных бликов или теней.

## Сохранение и точное продолжение

1. Начать Human-рисунок. После нескольких десятков мазков Pause & Save. Дождаться Saved и записать cursor/executed из projects/<id>/project.json. Кнопка мыши отпущена.
2. Закрыть программу через меню иконки. Сохранить игровой рисунок средствами самой игры, если они доступны. Перезапустить программу, открыть ту же работу в игре, Dashboard → Continue / Projects → Resume.
3. Должны загрузиться исходник, Preview, формат, заполнение краёв, режим и журнал. Выполненные индексы не повторяются; незавершённый мазок допустимо повторяется целиком. Проверить cursor до/после, отсутствие повторного начального слоя и сохранение ранних деталей.
4. На отдельной копии показать другой/пустой холст или изменить DPI/окно. Resume должен потребовать исправления геометрии либо явного подтверждения непроверенного холста. Нажать Cancel — **ни одного мазка**.
5. Проверить CALIBRATE → Use Current Calibration для сдвинутого холста прежнего физического размера. Подтвердить только после сравнения изображения.
6. Save As на паузе создаёт независимую копию. Delete Checkpoint на копии после подтверждения сбрасывает только прогресс. Оригинал сохраняется.
7. Для сбоя диска использовать тестовый путь/квоту, не основной проект: SAVE ERROR должен быть виден и ставить рисование на паузу; выход с несохранёнными данными требует отдельного решения.

## Остановка/отключение сервера

На тестовом рисунке переключить окно, свернуть игру, изменить клиентский размер, затем отдельно разорвать сеть/покинуть сервер. При обнаружении невозможности ввода/подтверждения приложение должно отпустить мышь, включить PAUSED и сохранить подтверждённый курсор. Между физическим отключением и очередной проверкой возможен интервал обнаружения; неподтверждённый хвост откатывается к последней проверке. После возвращения вручную открыть сохранённый холст и Resume. **Автоматически создавать заново очищенный серверный холст программа не может.**

Запустить второй экземпляр и попытаться рисовать, пока первый держит управление (включая паузу): второй должен сообщить о занятой мыши. Завершение первого освобождает блокировку.

## Поля, Discover и интерфейс

На вертикальной картинке с белой одеждой в квадратном холсте проверить все 8 режимов Smart Canvas Fill. Меняться должны только добавленные поля; одежда/лицо исходника сохраняются. Текст должен появиться и в DRAW PREVIEW, и в реальном рисунке. После Save/перезапуска настройки и положение текста те же.

Discover с обычным интернетом: настоящий поиск Commons, карточка с источником/автором/лицензией, Preview, Import, Favorites. Отключить сеть: избранное открывается из кэша, новый поиск показывает понятную ошибку. Никаких подставных результатов.

Во время планирования/рисования переключать разделы, перемещать окно программы на паузе, открывать Projects. UI должен реагировать; несовместимые действия во время ввода не запускаются. Live Art Core меняется только по выполненным мазкам, останавливается на паузе, завершение — ARTWORK COMPLETE.

Сохранить результаты вместе с версией Windows, DPI, размером клиентской области, профилем и commit проекта. Не публиковать API-ключи.
