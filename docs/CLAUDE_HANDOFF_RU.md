# Передача REDLAIN DRAW ENGINE в Claude Code

Состояние передачи: 27 октября 2026 года. Репозиторий: **https://github.com/REDLAIN228/Program**.

Программная основа: REDLAIN DRAW ENGINE 3.0.0, commit `b4777ce33a8ca0bdb3be57c35ca0fac9b022ed43`. Документы передачи добавляются отдельным commit поверх него. Ветка до обновления — `backup/pre-3.0`, commit `ee7c55d1062efd412c3767b2eec2194e68c1e1db`.

Это передача исходников, инженерного контекста и следующего задания. Claude Code не был автоматически запущен и не получил доступ к компьютеру пользователя. Нужно открыть этот репозиторий в своей сессии Claude Code и выполнить [точное задание](CLAUDE_TASK_RU.md).

## Что делает приложение

Программа загружает изображение, подготавливает его под физический игровой холст, строит Plan из нормализованных Stroke и выполняет их мышью/клавиатурой Windows через обычный интерфейс игры. Внешнего управления мышью на Linux нет: там используется собственный Qt-холст для проверок. Исходная цель — красиво копировать изображение/персонажа, а не обязательная AI-стилизация.

Пользователь сталкивался с тем, что старое сложное изображение занимало много часов. Требуется улучшать **фактически принятый рисунок**, а не просто скорость отправки событий. Опыт пользователя важнее формально красивого интерфейса.

## Карта архитектуры

Поток данных:

```text
Импорт / Capture / внешний AI
  → imaging + layout + canvas_fill
  → planner → painter / vector / human
  → Plan + Stroke + preview + masks
  → DrawingExecutor
  → PopupController / HSV / sliders / Win32Backend
  → реальные ввод и снимки игрового UI

DrawingExecutor → события → LiveArtCore
DrawingExecutor → checkpoint sink → ProjectWriter → ProjectStore
DiscoverPage → HTTP worker → CommonsClient → cache / Workspace
```

## Профили игры и история ошибок

Два интерфейса нельзя смешивать:

- Старый плейс: `roblox-free-slider-v5`, бесплатная кисть **1 слева → 256 справа**, непрозрачность **100% слева → 1% справа**. Донатная вкладка «Размер» и инструменты **6/7/8** исключены и защищены. HSV-круг/квадрат требуют правильной ориентации и чтения текущего цвета.
- Новый плейс: `roblox-popup-rgb-v4`. RGB и размер вводятся в числовые поля. Та же цветная кнопка открывает/закрывает перекрывающую холст палитру. Нужно подтвердить закрытие до рисования. Этого профиля нельзя лишать проверок ради ускорения.
- Готовые точки относительны к **клиентской области 1366×768**, не ко всему экрану. Положение/масштаб интерфейса и DPI требуют совпадения или повторной калибровки. Источник координат — app/game_profile.py; не превращай их в безусловные глобальные screen coordinates.

Ранее пользователь присылал ошибки: число дописывается к старому, Backspace удаляет, но ввод нового блокируется ложной проверкой пустого поля; RGB выбирается неверно; клик пропущен из-за задержки игры; большая кисть не меняется; повторные клики по уже выставленным контролам; хвост от палитры к старту тестовой линии; ложная ошибка TEST DRAW; полосы/пробелы и чрезмерное число точек; слишком медленно; Resume блокируется после изменения геометрии окна.

В коде уже есть исправления и регрессионные fixtures. Это **история, не список всех подтверждённых текущих багов**. Сначала воспроизвести, затем менять. Посмотри tests/test_popup_profile.py, test_windows_packets.py, test_draw_check.py, test_draw_feedback.py, test_slider.py, test_opacity.py, test_executor.py и tests/fixtures.

Известный native Qt exit crash исправлен: GuiBridge сравнивает threading.get_ident(), а не создаёт временную обёртку QThread.currentThread() ради сравнения affinity. Не возвращай этот паттерн без проверки clean shutdown. Qt-объекты создаются/меняются в UI-потоке; дисковый writer передаёт сообщения через очередь, которую читает UI-таймер.

## Что подтверждено и что остаётся проверить

Baseline 3.0: 261 автоматический тест на Linux/Qt offscreen; чистый exit 0. Есть тест отдельного Python-процесса, загрузка в новом MainWindow/Store и исполнение только оставшихся индексов. UI проверен на 1320×740 и 850×700. Передача повторно запускает тесты; результаты текущего прогона записаны в [проверках пакета](HANDOFF_VERIFICATION_RU.md).

Существующие raw измерения на одинаковых 128×128 app-local Qt-примерах:

| Пример | Vector 2.0 | Human FAST | BALANCED | MASTERPIECE |
| --- | --- | --- | --- | --- |
| portrait | 132 мазка / 7,487 с | 15 / 2,622 с | 31 / 4,231 с | 49 / 5,004 с |
| landscape | 141 / 8,505 с | 21 / 3,568 с | 35 / 4,326 с | 69 / 4,700 с |
| texture_text | 73 / 8,046 с | 20 / 2,977 с | 20 / 3,336 с | 20 / 4,116 с |

Это измеренное ускорение FAST 2,38–2,86×. Снимки имеют компромисс качества: landscape agreement у Vector 94,8%, FAST 92,3%, BALANCED/MASTERPIECE 93,5%. Чистота краёв ещё требует работы. Метрики не равны эстетическому качеству. Локальный Timing намеренно ускоренный и одинаков для сравнения; его нельзя применять в Roblox.

Живой Win32/Roblox, реальная регистрация высоких скоростей, игровой reconnect и EXE в этой Linux-среде не проверены. Windows workflow существует, но наличие YAML само по себе не доказывает успешный билд. Сценарий: [WINDOWS_ROBLOX_TEST_RU.md](WINDOWS_ROBLOX_TEST_RU.md). Не обещай 10–20× без измерений на одинаковых принятых рисунках.

Wikimedia Commons и api.github.com не входят в текущие разрешённые HTTP-хосты облачной среды; Commons ранее вернул ProxyError 403. Это ограничение среды, а не доказательство поломки клиента. В Windows поиск Commons не требует ключа, нужен доступ к commons.wikimedia.org/upload.wikimedia.org. Не обходи сетевую политику; повторно выясни доступность в своей среде. Внешний Images API требует пользовательский ключ; остальные функции не должны его требовать.

## Данные, которые нельзя потерять

Путь Windows — `%LOCALAPPDATA%\AnimeDrawer`; название специально сохранено после ребрендинга. Есть profiles.json/settings.json, images/plans/history/performance, discover и logs. Проекты — `projects/<id>/project.json` плюс **общая projects/.assets**. Копировать один манифест без .assets недостаточно. Для тестов задавай отдельный `ANIME_DRAWER_DATA_DIR`, не каталог пользователя.

Не повреждать: cursor и ledger executed/skipped; completed stages; source checksum и immutable assets; полный план оставшихся мазков; профиль/геометрию/DPI; режим, формат, поля/брендинг, приоритеты и накопленную статистику. Программа сохраняет план приложения, а не серверный Roblox-холст. Неизвестное состояние требует сравнения/подтверждения; исчезнувшая работа не восстанавливается продолжением с середины. Несохранённый старый процесс 2.0 нельзя восстановить задним числом.

## Что пользователь просит теперь

1. Сделать основной продукт проще: убрать лишние вкладки/дубли, оставить реально рабочие функции и понятный маршрут «Импорт → Preview → Проверка игры → Рисование → Сохранить/Продолжить».
2. Повысить **скорость и качество принятого рисунка**, устранить полосы/лишние штрихи/пропуски ввода. Сначала профилирование, затем изменения с before/after.
3. Создать новый цельный интерфейс: премиальный графит/белый/умеренный красный, удобный на небольшом экране, с анимациями запуска, раскрытия/скрытия, сворачивания, изменения размера, смены вкладок и режимов.
4. Добавить собственного анимированного визуального ассистента с ощущением объёма/3D, который во время работы рисует/готовится/отдыхает и реагирует на реальные события движка.
5. Добавить спокойный анимированный фон. Ассистент/фон/переходы должны отключаться и снижать нагрузку во время внешнего рисования.
6. Собрать Windows-дистрибутив и передать понятную инструкцию запуска и обновления.

## Что ещё НЕ сделано

Полноценного персонажа-ассистента и 3D/2.5D renderer нет. Нет единой системы переходов всех страниц/окон/размеров, гарантированно проверенных native window animations и анимированного фона. Текущий UI остаётся многослойной эволюцией 2.0/3.0 и требует упрощения. Автоматическое восстановление содержимого серверного холста не реализовано и не должно имитироваться. Нативные показатели скорости/надёжности ещё предстоит собрать. Совершенной семантической сегментации персонажей и гарантии «без ошибок» нет.

## Идеи для проверки, а не обещанные готовые функции

| Идея | Что измерить / от чего защититься |
| --- | --- |
| Отдельные измерения настройки цвета, размера, подтверждений и траектории | Найти доминирующие задержки; не вычитать их из ETA и не ускорять вслепую |
| Адаптивное ожидание по стабильности UI и истории задержек | p50/p95, bounded timeout/retry, отсутствие слепого повторного toggle, подтверждение конечного состояния |
| Кэш состояния контролов по target/profile/session | Инвалидация после паузы, смены окна/инструмента/геометрии/ошибки; не доверять устаревшему цвету |
| Cost-aware grouping по цвету/кисти внутри стадии | Меньше переключений и travel, но без перестановки перекрывающихся областей и разрушения тонких деталей |
| Coverage-aware соединённые траектории | Меньше отдельных точек, измеренная ширина реальной кисти, отсутствие выхода за маску/пересечения отверстий |
| Анализ residual между preview и принятым холстом | Выявлять ограниченный хвост пропусков; не исправлять уже принятый рисунок бесконечными точками |
| Приоритетные ROI лица/глаз и обоснованный small-detail cutoff | Сохранить узнаваемость при ограниченном физическом разрешении; не обещать «Full HD» на маленьком холсте |
| Единый renderer brush footprint и тесты rounded pixel mapping | Сократить расхождение Pillow/OpenCV/Qt/игровой кисти и артефакты края |
| Разделение MainWindow на контроллеры и явную state machine | Исключить повторные slots, конкуренцию jobs, неоднозначный Resume и автоматические повторные действия |
| Измеренные desktop animations / ассистент 2.5D или лёгкий 3D | Сравнить Qt Widgets/QPainter/Qt Quick без безусловного переноса всего приложения; GPU fallback и Reduce Motion |
| Четыре основные области вместо шести | Рисование с Live Core; Проекты; Настройки; Discover только после реальной проверки и как необязательное расширение |

Claude должен предложить собственные улучшения по фактам, сравнить варианты и реализовать полезные. Список не предписывает внедрить всё одновременно.

## Сборка и старт следующей сессии

Python 3.11–3.13 x64, PySide6 6.8.3, OpenCV headless 4.11.0.86, Pillow 11.2.1, NumPy 2.2.6, MSS 10, httpx 0.28.1, keyring 25.6.0. Точные зависимости — requirements.txt; pytest/PyInstaller — requirements-dev.txt.

Windows: `run.bat`; проверка — `run.bat --test-canvas`; сборка — `build.bat`, результат `dist\RedlainDrawEngine\RedlainDrawEngine.exe` вместе с `_internal`. Текущий builder намеренно требует Windows. В Linux исходники можно проверить и упаковать, но результат не называется собранным Windows EXE.

Полные стартовые команды и короткий промпт: [OPEN_IN_CLAUDE_RU.md](../OPEN_IN_CLAUDE_RU.md). Полное задание: [CLAUDE_TASK_RU.md](CLAUDE_TASK_RU.md). Работа должна закончиться кодом, измерениями, проверками и дистрибутивом в доступной среде, а не только новым макетом.
