# REDLAIN DRAW ENGINE — контекст для Claude Code

Репозиторий: https://github.com/REDLAIN228/Program

Это существующая Windows-программа Python/PySide6 для рисования через обычный UI Roblox. Продолжай этот проект; не создавай рядом другое приложение. Пользователь передаёт дальнейшую разработку Claude Code. Этот файл — контекст и правила работы, а не заявление о том, что Claude уже был запущен.

Начни с файлов:

2. [Точное задание пользователя на следующий этап](docs/CLAUDE_TASK_RU.md).
3. [Проверки версии 3.0](docs/V3_VALIDATION_RU.md) и [нативный сценарий](docs/WINDOWS_ROBLOX_TEST_RU.md).

## Обязательные ограничения

- Сохраняй пользовательские проекты, их точный cursor/executed/skipped, контрольные суммы, профили и возможность Resume. Не очищай `%LOCALAPPDATA%\AnimeDrawer` при обновлении или тестировании.
- При изменении формата проекта делай миграцию с резервной копией. Сохраняй загрузку формата 3 и старых планов/профилей, даже если соответствующие движки исчезнут из основного UI.
- F8/F9, отпускание мыши, проверки foreground/process/class/client-size/DPI, цвета/кисти, неизвестного холста и межпроцессная блокировка ввода обязательны. Скорость не достигается отключением этих проверок.
- Не используй Roblox injection, модификацию клиента, обход античита, скрытые API игры или покупки. В старом игровом профиле донатная вкладка «Размер» и инструменты 6–8 запрещены; бесплатный размер 1–256. В новом плейсе RGB и размер вводятся числами, палитра закрывается той же кнопкой, которая её открывает.
- Не принимай успешные Qt/mock-тесты за проверку живого Roblox. Локальные benchmark timing не переносить в игровые пресеты. Успешный SendInput сам по себе не доказывает регистрацию мазка сервером.
- Не используй фиктивные результаты поиска, случайный процент, искусственные ETA или ассистента, изображающего выполняемую работу при отсутствии соответствующего события.
- Упрощай интерфейс по результатам аудита зависимостей и проверки функций. Не называй модуль сломанным только из-за заблокированной сети или отсутствующего пользовательского API-ключа. Непроверенные интеграции убирай из основного сценария с честной пометкой/отключением.
- При удалении кода не удаляй тесты ради зелёного результата. Удаление теста допустимо только вместе с осознанным удалением функции и объяснением; для сохраняемых контрактов нужна прежняя или эквивалентная проверка.
- Новые анимации и 3D-ассистент не должны перехватывать ввод, перекрывать игровую палитру/холст или замедлять движок. Нужны Reduce Motion, режим слабого ПК и fallback без GPU; безопасное скрытие во время внешнего ввода важнее анимации.
- Рефакторинг и реализацию веди до рабочего результата: не ограничивайся макетом, аудитом или списком идей. Рутинные технические решения принимай самостоятельно. Реальные блокеры среды/недостающие данные описывай отдельно.

## Известная основа

Версия приложения 3.0.0, исходный commit передачи кода `b4777ce33a8ca0bdb3be57c35ca0fac9b022ed43`. До 3.0: `ee7c55d1062efd412c3767b2eec2194e68c1e1db`, ветка `backup/pre-3.0`. Новые документы передачи добавляются поверх 3.0; актуальный HEAD смотри через git, не сбрасывай ветку на baseline.

На 3.0 подтверждены 261 автоматический тест на Linux/Qt offscreen, точное продолжение в новом Python-процессе и новом UI-контроллере. Измеренное ускорение Human FAST относительно Vector 2.0 — 2,38–2,86× на трёх маленьких локальных примерах. Это не обещание 10–20× и не замер Roblox. У landscape есть потеря точности краёв. Полноценный 3D-ассистент, анимированный фон и полная система анимаций окна ещё не реализованы.

## Состояние 4.0 (этап выполнен поверх 3.0)

Отчёт с аудитом функций, сырыми замерами и ограничениями: [docs/V4_REPORT_RU.md](docs/V4_REPORT_RU.md). Пользовательская инструкция: [V4_GUIDE_RU.md](V4_GUIDE_RU.md). Ключевое для следующей сессии:

- `app/precise_wait.py`: исполнитель ждёт через `PreciseWaiter.pace()`. `threading.Event.wait` на Windows округляет короткие тайм-ауты до ~15,6 мс — не возвращай его в горячий путь. Контракт `DrawingExecutor._wait(seconds)` с одним аргументом используют тесты. `speed_calibration.TIMING_MODEL = 2`: калибровки 3.0 не включают быстрый сэмплинг.
- `time.monotonic()` на Windows/Python 3.12 тикает раз в ~15,6 мс; дедлайны, урезанные до остатка, считаются достигнутыми без опроса часов.
- `human.merge_close_colors` объединяет неразличимые оттенки (порог 18/12/7 для FAST/BALANCED/MASTERPIECE) только для свободной палитры.
- UI: `app/ui/shell.py` переразмещает виджеты, созданные слоями `panel → studio → v3`. Логика по-прежнему читает эти атрибуты. Неразмещённые виджеты живут в скрытом `shell.holder`. Анимации — только через `app/ui/motion.py` (`Animator`: одна анимация на свойство; `WindowMotion`). Перед вводом — `MainWindow._ensure_hidden()`.
- Декор: `backdrop.py` (перерисовываются только просветы между карточками, 20/10 к/с) и `assistant.py` (2.5D QPainter, 30/15/10 к/с). Он стоит, пока `motion.external_input` (DRAWING), и при скрытом или свёрнутом окне.
- Проверки 4.0 (Windows): `tools/benchmark_v4.py`, `tools/effects_impact.py`, `tools/v4_visual_smoke.py`, `tools/wait_resolution.py`, `tools/guard_cost.py`, `tools/halo_check.py`.

## Основные команды

Windows: `run.bat`, локальный холст — `run.bat --test-canvas`, EXE — `build.bat`. Результат: вся папка `dist\RedlainDrawEngine`, не один EXE.

Linux с существующим окружением:

```sh
QT_QPA_PLATFORM=offscreen .venv/bin/python -X faulthandler -m pytest -q
QT_QPA_PLATFORM=offscreen .venv/bin/python tools/gui_startup_smoke.py
QT_QPA_PLATFORM=offscreen .venv/bin/python tools/v3_visual_smoke.py
QT_QPA_PLATFORM=offscreen .venv/bin/python tools/benchmark_v3.py
```

Главная цель следующего этапа: меньше лишних экранов и действий, надёжнее игровой ввод, быстрее рисунок при измеренно сохранённом качестве, новый понятный интерфейс с ненавязчивой анимацией и собственным реактивным визуальным ассистентом.
